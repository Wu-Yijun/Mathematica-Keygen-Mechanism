# 07 — 数学原理

**中文** · [English](07-mathematics.md)

## 7.1 CRC 作为 GF(2) 上的算术

CRC 就是多项式除法。将比特串 `b_0 … b_{k-1}` 视为 GF(2) 上的多项式
`B(x) = Σ b_i x^{k-1-i}`，并将 16 位状态 `s` 视为次数 < 16 的 `S(x)`。
一个比特**步**（step）是

```
S(x) ← x·S(x) + b_i   (mod P(x))
```

其中*多项式* `P(x)`（次数为 16）由我们的 `poly` 常量编码，且**包含 x¹⁶ 项**：

```
P_A(x) = x^16 + x^12 + x^10 + x^9 + x^6 + x^3 + x + 1     (0x1064b)
P_B(x) = x^16 + x^12 + x^10 + x^8 + x^7 + x^6 + x + 1     (0x105c3)
```

馈入一个由 `n` 个字节组成的字节串 `D`，就是模运算下的 `x^{8n}` 乘后再加。

## 7.2 基本恒等式（以及为何一切皆可逆）

对于固定的 `n` 字节消息 `D`，从初始值 `s` 到最终 CRC 的映射是**仿射**的：

```
CRC_P(s, D) = ( s · x^{8n} mod P )  ⊕  CRC_P(0, D)
              └────── 关于 s 线性 ──┘    └── 对 D 为常量 ──┘
```

记 `S_k(s) = s · x^{8k} mod P`（前进 `k` 个零字节）。`S_k` 是 16 位状态上的一个**双射**，
而 `S_1` 有一个只需两条指令的逆：

```
S_1 (s) = ((s << 1) & 0xFFFF) ^ ((s >> 15) ? P : 0)
S_1⁻¹(y): t = y & 1;  return ((y ^ (t ? P : 0)) >> 1) | (t << 15)
```

现在把一个 2 字节的*前缀* `w` 从其余部分 `D` 中分离出来：

```
CRC_P(I, w ‖ D) = S_{n}( CRC_P(I, w) )  ⊕  CRC_P(0, D)
CRC_P(I, w)     = S_2(I) ⊕ L_P(w)                (L_P 线性且为双射)
```

因此对于任意期望的目标 `t`：

```
L_P(w) = S_n⁻¹( t ⊕ CRC_P(0, D) ) ⊕ S_2(I)      ⇒      w = L_P⁻¹( · )
```

这是一个在 GF(2) 上的**仿射（实际上线性）求解**，用 16×16 高斯消元计算 ——
**O(16²)，无需搜索**。`code/mathpass.ts` 正是实现了这一过程
（`solveLinear16`、`solveAppend2`）。

## 7.3 本方案的实例化

令 `MESSAGE = mathID@expiry$LicenseCode&activationKey`，`n = |MESSAGE|`。

* **条件 B（Accepted CRC）。** `M = CRC_{P_B}(0xA5B6, n0 ‖ MESSAGE)`。
  取 `w = n0`、`D = MESSAGE`、`I = 0xA5B6`：
  `n0` 由任意选定的 `M` 唯一确定，反之 `M` 由 `n0` 确定。
  因此设计者可以从白名单中自由选取 `M`，并求解出 `n0`。

* **条件 A（完整性）。** `0 = CRC_{P_A}(0xA5B6, n2 ‖ MESSAGE ‖ ω(n0))`。
  固定 `n0`（从而固定 `ω(n0)`）；同样的论证给出唯一的 `n2`。

因此这两个 16 位残差是两个*因变量*；自由参数是**白名单选择 `M`** 和消息本身。
该方案用 32 位证书钉住了 `2·16 = 32` 个比特 —— 恰好吻合，如同一个 CRC 校验和。

## 7.4 十进制编码（`v ↔ n`）是一个双射

```
n = ceil(v · 65535 / 99999)      (16-bit "hash" space, v ∈ [0, 99999])
v = floor(n · 99999 / 65535)     (5-digit decimal space)
```

再结合 [08](08-reconstructed-source.zh.md) 中固定的数字置换。这将 16 位残差映射到
5 位十进制组中，使密码全为数字。它是一个双射（其微小的向上取整松弛被
`ω(·)` 的往返吸收），并且**不贡献任何安全性** —— 它只是混淆与便于人工输入。

## 7.5 与公开 JavaScript 模型的关系

参考实现 `main@v14.1.0.js` 用 LSB 优先的哈希器和常量
`HASH_CODE_1 = 0x82E1`、`HASH_CODE_2 = 0x8325` 表达了同一方案。二进制中的
MSB 优先多项式是镜像形式：

```
P_B = 2·0x82E1 + 1 = 0x105c3
P_A = 2·0x8325 + 1 = 0x1064b
```

而 JavaScript 一侧将 CRC 与 `0xA5B6` 比较，这恰好就是二进制中的
**初始值**。换言之：

| | JavaScript | 二进制 |
| --- | --- | --- |
| "accepted CRC" | 初始值（`MathPass.hash`） | 条件 B 的*结果* |
| `0xA5B6` | 目标 | 初始值 |
| 约束 | `CRC == 0xA5B6` | `CRC ∈ table` |

两者是*同一个*仿射方程，只是针对不同的未知量求解。[code/selfcheck.ts](code/selfcheck.ts)
中的经验性检验证实，在真实许可证上，二进制所接受的 CRC 等于 JavaScript 模型所要求的初始值。

## 7.6 为何要如此设计？

- **验证廉价，生成廉价。** CRC 只有几次移位/异或；生成只需一次线性求解。
  无需大整数运算，无需密码学库，无需网络。
- **能抵御朴素篡改，但抵不住专门攻击。** 改动一位数字就会改变 CRC；
  随机猜测命条件 A 的概率为 `2⁻¹⁶`，命中白名单的概率为
  `21/2¹⁶`，即每次尝试约 `≈ 5·10⁻⁷`。
- **通过一张小表区分版本。** 单个二进制即可校验多个产品/版本，因为
  条件 B 只要求在 16 位密钥集合中具有成员资格。
- **它是类 MAC 的校验和，而非签名。** 因为 CRC 是*线性的*，任何知道
  `P_A`、`P_B`、`0xA5B6` 和白名单的人都能伪造任意许可证。设计者
  依赖的是多项式、初始值和白名单*未被记载*，而非*保密* —— 这正是
  本次逆向工程得以成功的原因。

### 经验性安全数据

对于真实消息，暴力破解初始值会找到**恰好一个**满足条件 B 的值
（`59222`），且它是表中的成员。没有该表的伪造者必须去猜 65536 个状态中
21 个之一，*并且*满足条件 A —— 一旦结构已知即可行，而盲猜则不可能。
